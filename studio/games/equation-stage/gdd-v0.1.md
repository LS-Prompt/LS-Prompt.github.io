# GDD: 식으로 움직이는 무대

> 슬러그 `equation-stage` · 버전 0.1 · 최종 수정 2026-11-11

## 1. 비전
- **한 줄 비전**: 식을 세우면 장면이 그 식대로 움직인다. 맞는 식은 딱 맞아떨어지고, 틀린 식은 눈에 보이게 어긋난다.
- **타깃 플레이어**: 문장제에서 "식 세우기"가 막히는 중1~중3. 휴대폰 세로 화면, 한 번에 5~10분.
- **핵심 감정**: "아, 그래서 틀렸구나"(납득) → "이번엔 딱 맞았다"(쾌감).
- **학습 원칙**: 답(숫자)이 아니라 **식**을 고르게 한다. 오답은 벌점이 아니라 재생해 볼 수 있는 단서다. 시간 제한을 두지 않는다.

## 2. 코어 루프
- **초 단위**: 카드를 슬롯에 놓는다 → 식이 완성되면 ▶ 재생 버튼이 켜진다 → 재생하면 장면이 식의 해(x)만큼 진행된다 → 조건(만남, 통과 등)이 맞았는지 장면과 수치로 확인한다.
- **스테이지 단위**: 문제 읽기 → 식 조립 → 재생 → (어긋나면) 힌트 보고 카드 교체 → 성공 → 별 획득 → 다음 스테이지.
- **메타**: 유형마다 스테이지 3개(조립 → 오답 탐정 → 조건 바꾸기). 별을 모으면 다음 유형이 열린다. 진행 상황은 기기에 저장된다.

## 3. 규칙
스테이지마다 문장제 하나와 **식 틀**(빈 슬롯이 있는 식)이 주어진다. 플레이어는 손패의 카드를 슬롯에 놓아 식을 완성하고 재생한다. 게임은 그 식을 실제로 풀어 x를 구한 뒤, 장면을 x만큼 진행시켜 문제의 조건이 성립하는지 보여 준다.

- **미지수**: P0에서는 "x = 무엇"을 스테이지가 미리 알려 준다(예: "준호가 달린 시간을 x시간이라 하자").
- **성공 조건**: 슬롯에 놓인 카드 구성이 스테이지의 정답 구성과 같을 것. 일차방정식은 해가 같으면 항상 동치이므로, 식의 구조는 카드 구성으로 판정한다(정답 구성이 여러 개인 스테이지는 모두 등록한다).
- **실패는 없다**: 틀리면 장면이 어긋난 모습으로 재생되고 힌트가 나온다. 횟수 제한 없이 다시 시도한다.
- **재생 결과 4종**
  | 결과 | 조건 | 장면 연출 |
  |---|---|---|
  | 정답 | 정답 식과 동치 | 조건이 정확히 성립(두 사람이 같은 지점에서 멈춤 등) + 축하 |
  | 어긋남 | 해는 있으나 오답 | x만큼 진행 후 차이를 수치로 표시(예: "준호가 88.5 km 앞서 있어요") |
  | 불가능한 해 | x가 음수 | 장면이 시작하지 못하고 "시간이 음수예요" 표시 |
  | 해 없음/무수히 많음 | x가 사라짐 | "x가 정해지지 않아요" 표시 |
- **대표 오답 인식**: 스테이지마다 대표 오답 식 2개를 등록해 둔다. 플레이어의 식이 그와 동치이면 그 오답에 맞춘 힌트를 준다. 그 외 오답은 일반 힌트.
- **별**
  | 별 | 조건 |
  |---|---|
  | ★★★ | 첫 재생에 성공 |
  | ★★ | 두 번째 재생에 성공 |
  | ★ | 세 번째 이후 성공, 또는 슬롯 힌트 사용 |
- **슬롯 힌트**: 오답 재생이 `hintAfterWrong`회 쌓이면 "틀린 칸 보기" 버튼이 나온다. 누르면 틀린 슬롯 하나가 표시된다.

### 스테이지 종류
| 종류 | 시작 상태 | 플레이어가 하는 일 |
|---|---|---|
| 조립 | 슬롯이 모두 비어 있음 | 카드를 골라 식을 완성하고 재생 |
| 오답 탐정 | 대표 오답 식이 채워져 있음 | 먼저 재생해 어긋남을 보고, 틀린 카드를 찾아 교체 |
| 조건 바꾸기 | 슬롯이 비어 있고 숫자가 매번 달라짐 | 같은 구조의 식을 새 숫자로 조립 |

## 4. 오브젝트
| 이름 | 역할 | 행동 | 플레이어와의 상호작용 |
|---|---|---|---|
| 문제 카드 | 문장제 제시 | 핵심 수치를 색으로 강조 | 읽기. 수치를 탭하면 장면의 해당 요소가 반짝임 |
| 무대(장면) | 식의 결과를 보여 줌 | 정지 → 재생 → 결과 표시 | ▶ 재생, ↺ 처음으로 |
| 식 틀 | 조립 대상 | 고정 토큰 + 빈 슬롯 | 슬롯 탭/드롭 |
| 카드 | 슬롯에 들어가는 조각 | 숫자 카드, 항 카드(`x + 1/3`, `x/2` 등), 연산 카드 | 탭하면 다음 빈 슬롯으로, 드래그하면 원하는 슬롯으로. 슬롯의 카드를 탭하면 손패로 돌아감 |
| 함정 카드 | 대표 오답을 만들 수 있는 카드 | 일반 카드와 똑같이 생김 | 골라서 재생하면 오답 장면과 맞춤 힌트 |
| 힌트 말풍선 | 오답 원인 안내 | 재생 후 등장 | 읽기, 닫기 |

## 5. 유형별 스테이지 설계 (P0·P1 대상: 거리·속력·시간 4유형)
숫자와 상황은 이 게임용으로 새로 만들었다. 대표 오답은 참고 자료의 유형별 오답 분류를 따른다.

### 유형 1 — 따라잡기 (직선 트랙)
- **문제**: 민지가 시속 3 km로 걸어서 먼저 출발했다. 20분 뒤 준호가 자전거를 타고 시속 9 km로 같은 길을 따라갔다. 준호는 출발한 지 몇 시간 만에 민지를 따라잡을까?
- **미지수**: 준호가 달린 시간 x시간
- **식 틀**: `3 × ( [항] ) = 9 × x`
- **정답**: `3 × (x + 1/3) = 9 × x` → x = 1/6시간(10분), 출발점에서 1.5 km
- **카드**: `x + 1/3` · `x + 20` · `x − 1/3` · `x`
- **대표 오답**
  | 오답 | 식 | 해 | 장면 | 힌트 |
  |---|---|---|---|---|
  | 분을 그대로 넣기 | `3(x + 20) = 9x` | x = 10 | 준호가 10시간을 달려 화면 밖으로 사라짐 | "속력이 시속이에요. 20분은 몇 시간일까요?" |
  | 시간 관계를 거꾸로 | `3(x − 1/3) = 9x` | x = −1/6 | 출발 불가 | "먼저 출발한 사람이 더 오래 걸었어요. 민지의 시간은 x보다 길까요, 짧을까요?" |
  | 시차를 빠뜨리기 | `3x = 9x` | x = 0 | 준호가 출발도 하기 전인데 민지는 1 km 앞에 있음 | "민지가 먼저 걸은 20분이 식에 없어요." |

### 유형 2 — 호수 둘레 반대 방향 (원형 트랙)
- **문제**: 둘레가 2.4 km인 호수의 같은 지점에서 하늘이는 분속 70 m, 바다는 분속 50 m로 서로 반대 방향으로 동시에 출발했다. 두 사람은 몇 분 뒤에 처음 만날까?
- **미지수**: 만날 때까지 걸린 시간 x분
- **식 틀**: `70 × x [연산] 50 × x = [수]`
- **정답**: `70x + 50x = 2400` → x = 20분
- **카드**: 연산 `+` · `−` / 수 `2400` · `2.4` · `240`
- **대표 오답**
  | 오답 | 식 | 해 | 장면 | 힌트 |
  |---|---|---|---|---|
  | km와 m를 섞어 쓰기 | `70x + 50x = 2.4` | x = 0.02 | 두 사람이 거의 움직이지 않고 멈춤 | "속력은 분속 몇 m예요. 둘레도 같은 단위로 바꿔 볼까요?" |
  | 거리의 차로 세우기 | `70x − 50x = 2400` | x = 120 | 두 사람이 여러 번 스쳐 지나감 | "반대 방향으로 돌면 두 사람이 간 거리를 합쳐야 한 바퀴가 돼요." |

### 유형 3 — 속력이 다른 왕복 (직선 트랙)
- **문제**: 등산로를 올라갈 때는 시속 2 km, 같은 길을 내려올 때는 시속 4 km로 걸었더니 모두 1시간 30분이 걸렸다. 등산로의 길이는 몇 km일까?
- **미지수**: 등산로의 길이 x km
- **식 틀**: `[항] + [항] = [수]` (평균 속력 오답용으로 항 슬롯 하나는 비워 둘 수 있음)
- **정답**: `x/2 + x/4 = 3/2` → x = 2 km
- **카드**: 항 `x/2` · `x/4` · `2x/3` · `2x` · `4x` / 수 `3/2` · `90` · `1.3`
- **대표 오답**
  | 오답 | 식 | 해 | 장면 | 힌트 |
  |---|---|---|---|---|
  | 분을 그대로 넣기 | `x/2 + x/4 = 90` | x = 120 | 산이 화면 밖까지 늘어남 | "속력이 시속이에요. 1시간 30분은 몇 시간일까요?" |
  | 두 속력의 평균으로 계산 | `2x/3 = 3/2` | x = 9/4 | 실제로 걸어 보니 1시간 41분이 걸림 | "느린 속력으로 걷는 시간이 더 길어요. 올라갈 때와 내려올 때 시간을 따로 구해 볼까요?" |

### 유형 4 — 기차의 터널 통과 (직선 트랙)
- **문제**: 길이가 200 m인 기차가 초속 25 m로 달려 길이 800 m인 터널을 완전히 통과하려면 몇 초가 걸릴까?
- **미지수**: 완전히 통과하는 데 걸리는 시간 x초
- **식 틀**: `25 × x = 800 [연산] [수]` (기차 길이를 빠뜨리는 오답용으로 뒤 두 슬롯은 비워 둘 수 있음)
- **정답**: `25x = 800 + 200` → x = 40초
- **카드**: 연산 `+` · `−` / 수 `200` · `25`
- **대표 오답**
  | 오답 | 식 | 해 | 장면 | 힌트 |
  |---|---|---|---|---|
  | 기차 길이를 빠뜨리기 | `25x = 800` | x = 32 | 기차 머리만 나오고 꼬리가 터널 안에 남음 | "기차 꼬리가 아직 터널 안에 있어요. 머리는 얼마나 더 가야 할까요?" |
  | 기차 길이를 빼기 | `25x = 800 − 200` | x = 24 | 기차가 터널 안에 완전히 들어간 채 멈춤 | "'완전히 통과'는 꼬리까지 나오는 거예요. 머리가 간 거리를 그려 볼까요?" |

### 조건 바꾸기용 숫자 묶음
스테이지마다 해가 깔끔하게 나오는 숫자 묶음을 3개 이상 준비하고 무작위로 고른다(직전과 같은 묶음은 피한다). 유형 1 — 조립: (시속 3 km, 20분, 시속 9 km) / 오답 탐정: (시속 4 km, 15분, 시속 6 km) / 조건 바꾸기: (시속 4 km, 30분, 시속 12 km), (시속 3 km, 30분, 시속 6 km), (시속 5 km, 12분, 시속 15 km).

## 9. UI 화면 흐름
세로 화면 기준, 위에서 아래로 **문제 → 무대 → 식 틀 → 손패 → 재생 버튼** 한 줄 배치. 가로가 넓은 화면에서는 무대를 왼쪽, 식과 손패를 오른쪽에 둔다(P1. 스프린트 1에서는 가운데 한 열로 표시).

| 화면(`state.scene`) | 목적 | 표시 요소 | 입력 | 다음 화면 |
|---|---|---|---|---|
| title | 시작 | 제목, "시작" 버튼, 음소거 | Enter/탭 | map |
| map | 유형·스테이지 선택 | 유형 4칸(잠금 표시), 스테이지 3개씩, 획득한 별 | 스테이지 탭 | stage |
| stage | 플레이 | 문제 카드, 무대, 식 틀, 손패, ▶ ↺ 힌트 버튼 | 8장 조작 표 | (재생) playing |
| playing | 식 재생 | 무대 애니메이션, 경과 시간 표시. 조작 잠금 | 탭하면 건너뛰기 | result |
| result | 결과 확인 | 정답: 별과 "다음" 버튼 / 오답: 차이 수치, 힌트 말풍선, "다시" 버튼 | 탭/Enter | stage 또는 map |

- 첫 스테이지에서만 손가락 아이콘이 "카드 → 슬롯 → ▶" 순서를 한 번 안내한다.
- 탭 전환 시 재생 중이던 애니메이션은 일시정지하고, 돌아오면 이어서 재생한다.

## 10. 아트 방향
- **팔레트** (`CONFIG.colors`)
  | 이름 | HEX | 용도 |
  |---|---|---|
  | bg | `#F7F4EC` | 종이색 배경 |
  | ink | `#1F2A44` | 글자, 선 |
  | stage | `#FFFFFF` | 무대 바닥 |
  | actorA | `#E4572E` | 인물 A(먼저 출발한 쪽 등) |
  | actorB | `#17809A` | 인물 B |
  | accent | `#F2B134` | 강조 수치, 격차 표시 |
  | good | `#2E8B57` | 정답 |
  | bad | `#C0392B` | 어긋남 |
- **도형 언어**: 인물은 둥근 도형(A는 원, B는 둥근 사각형)으로, 색과 모양 두 가지로 구분한다. 기차·터널은 긴 사각형. 카드는 모서리가 둥근 종이 조각, 슬롯은 점선 테두리.
- **가독성 규칙**: 문제 속 수치와 무대의 해당 요소는 같은 색으로 표시한다. 어긋남은 색뿐 아니라 차이 구간에 사선 무늬와 수치 라벨을 붙인다.
- 그래픽은 모두 Canvas 도형으로 그린다. 외부 이미지는 쓰지 않는다.

## 11. 사운드
| 이벤트 | 파형 | 주파수 변화 | 길이 | 의도 |
|---|---|---|---|---|
| 카드 집기 | triangle | 520 → 620 Hz | 60 ms | 가벼운 반응 |
| 카드 놓기 | triangle | 440 → 330 Hz | 80 ms | "착" 하고 들어가는 느낌 |
| 재생 시작 | sine | 330 → 660 Hz | 180 ms | 기대감 |
| 정답 | sine 3음 | 523 · 659 · 784 Hz 차례로 | 420 ms | 성취감 |
| 어긋남 | sawtooth(낮은 볼륨) | 220 → 160 Hz | 220 ms | 실패가 아니라 "어라?" 정도의 부드러운 신호 |
| 별 획득 | square(낮은 볼륨) | 880 → 1320 Hz | 90 ms × 별 수 | 보상 |

자주 나는 카드 소리는 피치를 ±5% 무작위로 바꾼다. AudioContext는 첫 입력 후 만든다.

## 12. 기술 메모
- **구조**: `public/games/_template/`의 CONFIG / state / input / sfx / update(dt) / render() / 고정 타임스텝 루프를 따른다. 퍼즐 게임이므로 씬은 템플릿의 `playing/paused/gameover` 대신 `title → map → stage → playing → result`를 쓴다. `window.__game = { CONFIG, state, ... }` 디버그 핸들을 유지해 스모크 테스트가 "시작 후 씬 ≠ title"을 확인할 수 있게 한다.
- **식 계산**: 부동소수 오차를 피하려고 **유리수(분자/분모)** 연산을 쓴다. 식의 양변을 일차식 `a·x + b`로 정리한 뒤 푼다. 결과는 `유일한 해 / 해 없음 / 무수히 많음`으로 분류한다.
- **동치 판정**(대표 오답 인식용): 플레이어의 식과 대표 오답 식을 `(a좌 − a우, b좌 − b우)`로 정리해 비례 관계인지 비교한다.
- **스테이지 데이터**: 코드와 분리된 `STAGES` 배열. 항목마다 문제 문장(수치 자리표시자), 미지수 설명, 식 틀 토큰, 카드 목록, 정답 슬롯 값, 대표 오답 2개(슬롯 값과 힌트), 장면 종류와 매개변수, 조건 바꾸기용 숫자 묶음을 가진다.
- **장면 엔진**: `scene.positionsAt(t)`가 시각 t의 위치를 돌려주는 순수 함수. 종류는 `line`(직선)과 `loop`(원형) 두 가지로 시작한다. 재생은 0 → x를 `playDuration` 동안 ease-in-out으로 보간한다.
- **저장**: `localStorage[storageKey]` = `{ stars: { "1-1": 3, ... }, muted: false }`. 읽기·쓰기는 try/catch.
- **성능**: 정지 화면에서는 입력이나 애니메이션이 있을 때만 다시 그린다.

## 13. 범위
- **P0 (플레이 가능)**: 유형 1의 스테이지 3종(조립 · 오답 탐정 · 조건 바꾸기), 직선 트랙 장면, 슬롯식 조립, 유리수 식 계산, 재생 결과 4종, 대표 오답 힌트, title → map → stage → result 흐름, 터치·키보드 입력.
- **P1 (재미·손맛)**: 유형 2~4(원형 트랙 포함), 별과 유형 잠금 해제, 진행 저장, 슬롯 힌트, 사운드, 정답 축하 연출, 첫 스테이지 안내.
- **P2 (연출·부가)**: 재생 전 "예측하기"(만날 지점 찍기), 미지수 x를 플레이어가 직접 고르기, 토큰을 자유롭게 나열하는 자유 조립 모드, 다른 무대(비커 · 나눠 주기 · 일 막대 · 좌표)로 나머지 20유형 확장.
- **하지 않을 것**: 시간 제한·생명·랭킹, 계산(방정식 풀이) 연습, 계정·서버 저장, 광고·결제.
