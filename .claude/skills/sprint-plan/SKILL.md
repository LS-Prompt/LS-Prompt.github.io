# 스프린트 계획

`producer` 에이전트의 규칙을 따른다.

1. `gdd.md`, 기존 `sprint-*.md`, 최근 `playtest-*.md`를 읽는다.
2. 지난 스프린트가 있으면 완료/미완료를 정리하고 미완료 항목을 이월할지 결정한다.
3. 새 스프린트 번호 N으로 `studio/templates/sprint.md`를 채워 `studio/games/<slug>/sprint-N.md`에 저장한다.
   - 첫 스프린트 목표는 항상 "P0 코어 루프가 처음부터 게임오버까지 플레이 가능".
   - 항목마다 담당 에이전트, 완료 조건(검증 가능한 문장), 크기(S/M/L). L은 쪼갠다.
   - 플레이테스트 이슈 중 치명/높음은 이번 스프린트에 반드시 포함.
4. 항목 수는 S 기준 8~12개 이내로 제한한다. 넘치면 P2부터 다음 스프린트로 미룬다.
다음 단계: `/prototype`.
